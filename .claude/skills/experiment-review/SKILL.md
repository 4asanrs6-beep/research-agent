## 全体の流れ

```
Step 0: 結果の要約
  ↓
Round 1: 「なぜこの結果になったか」の原因切り分け（5ロール並列）
  ↓
原因仮説の整理（問い編集者）
  ↓
Round 2: 原因仮説を踏まえた「次に何をすべきか」（5ロール並列）
  ↓
結果から生まれた新しい仮説の整理（問い編集者）
  ↓
Codex裁定
```

## Step 0: 結果の要約（自分が書く）

- 何を検証したか（1文）
- 結果（主要数値）
- 捨てる条件に抵触したか
- 予想外だった点
- 有意だった変数と有意でなかった変数

## Round 1: 「なぜこの結果になったか」

5ロールを並列起動。**判断（A/B/C/D）はまだ出さない。** 原因の切り分けに集中。

### 各ロールへの問い

#### PM
「この結果はトレード戦略としてどう解釈するか」
- 効果がないのか、捉え方が間違っているのか
- 有意だった変数（ボラ等）は何を意味するか
- この結果から見える別のトレード機会は

#### 需給アナリスト
「需給メカニズムのどこが間違っていたか」
- 変数の選び方（水準 vs 変化率 vs 条件付き）
- タイミング（遅行指標 vs 同時指標）
- 需給の別の切り口

#### クオンツ
「統計設計のどこが結果に影響したか」
- 検出力は十分だったか（サンプルサイズ、自由度）
- 推定方法の問題（クラスターSE、demean等）
- 有意だった変数から何が分かるか

#### データ/実装
「データ制約が結果をどの程度歪めたか」
- 欠損率の影響
- 頻度制約（週次 vs 日次）の影響
- 別のデータソースで改善可能か

#### レッドチーム
「この結果の別の読み方はあるか」
- 効果がないのではなく、条件付きで効いている可能性
- 見落とされているサブサンプルやレジーム
- 有意だった変数自体に新しい問いが隠れていないか

### 各ロールの出力形式

- 原因仮説: なぜこの結果になったか（1-2文）
- 信頼度: この原因仮説にどの程度確信があるか（高/中/低）
- 得られた知見: この結果から確実に言えること（1文）
- まだ分からないこと: この結果だけでは判断できないこと（1文）

## Round 1後: 原因仮説の整理（問い編集者）

5ロールの原因仮説を整理する。

```
原因切り分け:
  (a) 仮説自体が間違い（信用残は超過下落に本当に効かない）
  (b) 変数の誤指定（信用残の捉え方が間違い。水準、変化率、条件付き等）
  (c) データ制約（週次、欠損、カバレッジ）
  (d) 統計設計（検出力不足、クラスターSE、イベント定義）
  (e) その他

各ロールがどの原因を支持しているか整理。
最も可能性の高い原因と、判定に必要な追加情報を明示。
```

## Round 2: 「次に何をすべきか」

5ロールを再起動。原因切り分けの結果を踏まえて、次のアクションを議論。

### 各ロールへの問い

Round 1の原因仮説整理を見た上で:
- 推奨アクション（**以下の4択から1つ**）
- その根拠（1文）
- やるべきでないこと（1文）

### 裁定の選択肢（4択）

1. **不備修正して再実行** — 実験設計にバグや欠陥があり、結果自体が信頼できない。不備を直してから同じ問いを再実行する。問いは変えない
   - 例: データ脱落の偏り、変数の計算ミス、サンプル選択バイアス
   - 次のアクション: 不備を特定→修正→再実行→改めて結果議論
2. **修正して再実験** — 結果は信頼できるが、問いや設計を変えて再挑戦する価値がある
   - 例: 変数の差替え、検出力の改善、非線形モデルへの変更
   - 次のアクション: v3を定義してPhase 3へ
3. **棄却確定** — この問いは閉じる。知見は保存
4. **次の問いに移る** — 別の問い（cq5, q11等）に着手

## Round 2後: 整理（問い編集者）

2つを分けて整理する:

### A. 修正版の問い（修正する場合）

```
- v3の内容
- v2からの変更点
- 捨てた案
- 未解決の弱点
```

### B. 保存する知見と活用案

```
知見:
  - この実験から確実に言えること
  - 予想外だった発見

活用案（知見の引き出しに保存。今すぐやるものではない）:
  - この知見を将来どう使えるか
  - どの問いに発展させられるか
  - 発展させる場合にPhase 1(brainstorm)に投入する起点になる
```

活用案は裁定ではなく知見の付属情報。
人間が判断すれば、活用案をbrainstormに投げて新サイクルを回せる。
自動では回さない。

## Codex裁定

全ロールの議論と問い編集者の整理を見て最終裁定。

**裁定は必ず1つに絞る。並行トラックは出さない:**
- **不備修正して再実行**: 実験設計の欠陥を直して同じ問いを再実行
- **修正して再実験**: 問い自体を修正（v3）して再びPhase 3へ
- **棄却確定**: この問いは閉じる
- **次の問いに移る**: 別の問い（cq5, q11等）に着手

裁定には必ず:
- 判定理由
- 未解決の最重要論点
- 保存すべき知見（活用案を含む）
を含める。

```markdown
## 整理

判定(1つ) / 理由 / 未解決論点 / 保存する知見+活用案

```

## 知見の蓄積

保存した知見と活用案は `logs/experiments/knowledge.md` に蓄積する。
将来のbrainstormやmulti_perspectiveで参照可能にする。

### 知見の記録ルール

1. **全実行の数値を併記する** — 不備修正前/後、v2/v3等の全結果を表形式で並べる。1回の数値だけ引用しない
2. **一貫した知見と矛盾した点を分けて記載する** — 複数回で一貫していれば信頼度が高い。矛盾していれば注意が必要
3. **最終裁定を含める** — 棄却/修正/進行中
4. **活用案は一連の実験全体を踏まえたものにする** — 単一実行の数値ではなく、全体の傾向に基づく
