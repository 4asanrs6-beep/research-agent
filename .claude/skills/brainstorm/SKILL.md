## 研究テーマ
$ARGUMENTS

## あなたの仕事

**知見のパターン全体から統合的な問いを導出する。**

### やること
1. `logs/experiments/knowledge.md` を読み、確定した知見を把握する
2. 知見を個別にではなく**パターンとして**読む。「Aが効く、Bが効く、Cが効かない、Dが効かない」の4つが同時に成立するという事実そのものから問いを導く
3. **3-5問だけ**に厳選する

### 問いの条件（厳守）

**良い問い = 知見の複数を同時に使わないと立てられない問い**

- 1つの知見だけから導ける問いは浅い。棄却すること
- 2つ以上の知見の**組み合わせ**からしか導けない問いだけを残す
- 各問いに**二段構えの判定基準**を含めること。「Xを確認し、さらにYも確認する。両方成立すれば…」という形

### 問いに含めるべき要素
各問いに以下を含めること：
- **使っている知見**: この問いはF1〜F4のどれとどれの組み合わせから導かれたか
- **これが分かると何が決まるか**: この問いの結果で、以降の仮説空間がどう狭まるか
- **検証方法の概要**: 1-2文
- **難易度**: low/medium/high

### 仮説は内部の思考に留める
仮説は問いを導くための思考の足場として使ってよいが、出力には含めない。出力は**問いだけ**。

## 深い問いの基準（few-shot例）

以下は知見F1-F4から導かれた深い問いの実例。**このレベルの深さ・具体性・二段構えを必ず出すこと。**

### 例1（使う知見: F1+F2）
> ボラと回転率は同じ潜在因子を測っているのか、独立した2つのチャネルか。F1とF2が両方有意ということは、(a)共通の潜在因子（例:投機的資金の集中度）の2つの表出か、(b)異なるメカニズム（例:ボラ=怖さ、回転率=売りやすさ）が同時に効いているか、のどちらか。ボラを統制した残差回転率、回転率を統制した残差ボラ、それぞれ単独で超過下落を説明するか検証する。片方が消えるなら同一因子、両方生き残るなら独立チャネル。
>
> **これが分かると:** メカニズムが1つなのか2つなのかが確定する。以降の仮説空間が半分になる。

### 例2（使う知見: F1+F2+F3）
> 超過下落は情報の反映か、流動性の一時的枯渇か。F3（β非有意）は「市場リスクの再評価ではない」ことを示す。もし情報イベントなら下落は永続的で反転しない。流動性イベントなら数日以内に反転する。高ボラ・高回転群の後5日累積超過リターンを見る。**さらに**、反転幅がS&P500の下落幅と無相関なら、米国発の情報ではなく日本市場内部の需給現象という証拠がさらに強まる。
>
> **これが分かると:** 「なぜβが効かないか」の答えが出る。活用法が逆張りか回避かも決まる。

### 例3（使う知見: F1+F2+F3+F4）
> 同じ知見パターンは米国急騰日でも対称的に成立するか。高ボラ・高回転の日本株は超過「上昇」するか。対称なら増幅器、非対称ならパニック固有。**同時に**βと信用残が上方ショックで復活するかも確認する。もしβが上方では有意になるなら、下方だけβが効かない理由はパニック時の意思決定ルールの変質にある。
>
> **これが分かると:** メカニズムが「増幅」か「パニック固有」かが確定。仮説の大半を一発で棄却できる。

### 例4（使う知見: F1+F2+F4）
> F4の符号反転は「信用残が下落を吸収している」証拠か。もし信用買い残が多い銘柄で押し目買いが入っているなら、(a)当日の超過下落は同等だが翌日以降の回復が速い、(b)ショック前後で信用買い残が増加。**この2条件が同時に成立すれば**、F4は「効かない」のではなく「下落と相殺する方向に効いている」ことになり、信用残を反転タイミングの指標として復活させられる。
>
> **これが分かると:** 信用残を捨てるか反転指標として復活させるかが決まる。

### ❌ 浅い問いの例（これは出すな）
- 「ボラの時間窓を変えたら？」— F1だけ。判定基準が一段
- 「βの代わりにクロスβなら？」— F3だけ。変数の入れ替えにすぎない
- 「交互作用は有意か？」— 統計的テクニックの確認。知見の深い組み合わせがない
- 「mean reversionはあるか？」— 判定基準が一段で二段構えがない

## 利用可能なデータ（前提知識）
- 日本株: 株価日足、信用取引（買残/売残）、財務、空売り比率、セクター17/33分類
- 米国株: 個別株・ETF日足、VIX、USDJPY
- 既存分析: イベントスタディ（ペア別CAR）、ネットワーク分析、Lead-Lag PCA、Qlib ML
- 制約: 日次データ中心。リアルタイムは15分遅延。日米取引時間差あり

## 出力形式（Claude/Codex共通スキーマ）

```json
{
  "source": "claude",
  "findings_used": [
    "F1: ...",
    "F2: ..."
  ],
  "questions": [
    {
      "id": "kebab-case-の英語短縮名（例: symmetry-test, holder-instability）",
      "question": "問い（3-5文。背景・予測・二段構えの判別基準を含む）",
      "findings_leveraged": ["F1", "F2"],
      "what_this_decides": "この結果で何が決まるか（1-2文）",
      "first_step": "検証の第一歩（1-2文）",
      "difficulty": "low|medium|high"
    }
  ],
  "total_questions": 5
}
```

## 問いのID命名規則（厳守）
- `q1`, `cq3` のような連番は使わない（サイクルをまたぐとかぶる）
- **問いの内容を表すkebab-caseの英語短縮名**を使う
- 例: `symmetry-test`, `holder-instability`, `attention-penalty`, `margin-shock`
- IDはすべてのログ（brainstorm, multi-perspective, conversation, experiments）で一貫して使う

## 禁止事項
- 実装手法への言及
- 1つの知見だけから導ける浅い問い
- 判定基準が一段だけの問い（二段構え必須）
- 検証不可能な問い
- knowledge.mdの棄却済み実験の焼き直し
- 10問以上の大量生成

出力はJSONのみ。結果を logs/iterations/brainstorm.json に保存してください。
